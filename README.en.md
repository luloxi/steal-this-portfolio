# Steal this portfolio! 🦝

A portfolio skeleton. The name, copy, projects and colors come from D1 and are edited in admin mode, not from GitHub. One example deploy is live at **https://lulox.com.ar**.
It's a simple, bilingual (ES/EN) portfolio with a blog, an inline admin editor and a simple contact form, running on one Cloudflare Worker.
Fork it, swap the content, deploy. That's the whole idea. ✨
It's copyleft on purpose: take it, make it better, and keep it open for the next person. 🏴‍☠️

## ✨ Features

- 🏠 **Landing** (two paths): see «Done for you» below for the new structure. Hero: "The repetitive stuff runs itself. You get back to what matters." with See the recipes and Get it done for me; then Pick your path, Recipes to get started, And much more, If you'd rather have it built for you, About, Tested every day, FAQ and the closing CTA. Fixed header with a mobile menu button; light and dark themes; reduced motion keeps everything still.
- 🧭 **Done for you** (`/servicios`, `/en/services`): one page with what you can get, what you can take off your plate, custom systems, how it goes and a closing CTA. The 5 old per-need pages (`/servicios/<slug>`, `/en/services/<slug>`) 301 to their card (`/servicios#<slug>`), listed in `src/lib/service-redirects.ts`. The home now has two paths (copy a recipe / done for you), a Recipes · Done for you · About · Contact menu, recipe CTAs that open the contact modal with the message prefilled, and blog, projects and referrals in the footer. Copy is second person and benefit-first, never "cheap". New copy keys (`landing.home.hero.*`, `paths.*`, `featured.*`, `end.*`) so old D1 overrides no longer apply; the saved D1 FAQ gets the 2 new `faq.extra` questions first if missing (`withExtraFaq`).
- 🎁 **Free recipes** (`/recetas`, `/en/recipes`): the "copy it yourself" path, as a recipe book. Wide grid (up to ~1240px, 1 column on phones, 2 on desktop) of cards with an own SVG illustration (`src/components/recipe-art.tsx`), title, benefit and two buttons: "Use the recipe" reveals the prompt (hidden by default) with Copy, what you need and 3 short steps; "Get it working" opens the contact modal with the recipe mentioned. Prompts drive themselves (`guided()`): the AI introduces itself, asks which tool you use (Grok, Grok Bot or Hermes), checks connectors, integrations, MCP or scheduled tasks, walks you through what is missing (or offers a plan B), asks questions to fill in the details, builds it, tests it with you and points to the contact page if you get stuck. Ends with "Get a hand". Content in `src/content/recipes.ts`.
- ♿ **Accessibility**: opaque cards and panels in both themes (`--card-solid` in `globals.css`), visible focus everywhere (inset ring on cut-corner cards), landmarks (`main`/`nav`/`aside`) in `PageShell`, AA contrast checked with axe and Lighthouse in light and dark at 390 and 1280 px, and a global `prefers-reduced-motion` safety net.
- ✍️ **Blog** with a rich-text editor (H1 to H3, bold, italic, underline, links and images uploaded to R2), drafts, cover images and drag-and-drop section reordering.
- 👤 **Sobre mí** (about): your story, experience cards and your publications (article citations), editable inline when you're signed in as admin.
- 🧪 **Proyectos**: project cards and detail pages. Each project's text uses the same editor as the blog.
- 💸 **Contratar** (hire me): what I can do (AI agents and automations) and a simple form (name, email and a message of up to 1000 characters) that reaches you by email.
- 🌗 Dark and light themes, 🇦🇷/🇺🇸 Spanish and English.
- 🎛️ Profile photo menu (admin only): "Edit mode" (tap any text on the landing or the About page and change it in place) and "Site settings" (pages, profile, colors and access), all saved to D1.
- 🔐 Google sign-in for anyone; admin only for the emails you allow.
- 🤝 **Referrals**: anyone with a Google account creates a code and earns 15% of what the client they bring pays; payout register for the admin.
- 📊 **Visits**: Cloudflare Web Analytics (cookieless) plus a first-party D1 counter, also cookieless and with no IP. The admin sees them at `/admin/visitas` (profile photo menu), with visits per day, per source, and ready-to-paste UTM links for Instagram, LinkedIn, X and email.

## 🧰 Stack

- [Next.js](https://nextjs.org) (App Router) built for Cloudflare with [OpenNext](https://opennext.js.org/cloudflare)
- [Cloudflare Workers](https://developers.cloudflare.com/workers/) + **D1** (SQLite) + **R2** (media) + Rate Limiting + [Web Analytics](https://developers.cloudflare.com/web-analytics/)
- [Better Auth](https://www.better-auth.com) with Google sign-in
- [Resend](https://resend.com) for the contact form email (Cloudflare Email Routing `send_email` as fallback)
- Tailwind CSS 4, TypeScript, `tsx --test` for tests

## 🚀 Quick start

You need **Node.js 24.22.1+** (the latest LTS; pinned in `.nvmrc`, run `nvm use`) and a free Cloudflare account (only for deploying).
**pnpm is recommended** (the repo pins it in `package.json`); npm works too.

```bash
# 1. Install
pnpm install                 # or: npm install

# 2. Env vars (local secrets, git-ignored)
cp .dev.vars.example .dev.vars
# fill in BETTER_AUTH_SECRET, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, TURNSTILE_SECRET_KEY (RESEND_API_KEY optional; MCP_SERVICE_TOKEN only for /api/mcp)

# 3. Local database (D1 in .wrangler/state) + sample posts
pnpm db:migrate:local        # or: npm run db:migrate:local
pnpm seed:blog               # or: npm run seed:blog

# 4. Run it
pnpm dev                     # or: npm run dev  → http://localhost:3000
```

### ☁️ Deploy to Cloudflare

1. `npx wrangler login`
2. Create your own resources and put their names/ids in `wrangler.jsonc`:
   - `npx wrangler d1 create <your-db>` (copy `database_id`)
   - `npx wrangler r2 bucket create <your-bucket>` (`MEDIA`). `BLOG_ASSETS` on this deploy points at the existing bucket `serpix-assets`: do not create it. If you fork, point it at yours or remove the binding
   - change `name`, `routes` (your domain), the `send_email` destination and `vars` (`CONTACT_TO`, `CONTACT_FROM`, `CONTACT_INBOX`)
3. `pnpm db:migrate:remote` (the script uses the `DB` binding from `wrangler.jsonc`, not the db name, so no need to edit `package.json`)
4. Set secrets: `npx wrangler secret put BETTER_AUTH_SECRET` (same for the Google ones, `TURNSTILE_SECRET_KEY`, `RESEND_API_KEY` and, for MCP, `MCP_SERVICE_TOKEN`)
5. `pnpm run deploy` (if it fails the first time, just run it again)

**Do this first** 👇

- `src/lib/auth/options.ts`: `ALLOWED_HOSTS` and `TRUSTED_ORIGINS` (your domains, or sign-in will refuse them).
- `public/`: replace the photos (`avatar*.jpg`), project images and logos.
- Site icon (favicon, Apple Touch, PWA): the "lx" monogram on a full-bleed black background; the "l" is a vertical gradient from yellow `#F6CD35` (top) to orange `#E2781B` (bottom). The vector master is `brand/lulox-logo.v5.svg` (`linearGradient`); the recalculated PNG is `brand/lulox-logo-master.png`. `python3 scripts/make-icons.py` generates the opaque Apple Touch and PWA PNGs in `public/icons`; the tab favicon (transparent, cropped) is generated by `python3 scripts/make-tab-favicon.py`. If you fork, replace `brand/` and run the scripts.

- **Two-language URLs:** Spanish lives at the root and English under `/en` with translated routes: `/` ↔ `/en`, `/contratar` ↔ `/en/hire`, `/sobre-mi` ↔ `/en/about`, `/proyectos(/<id>)` ↔ `/en/projects(/<id>)`, `/contacto` ↔ `/en/contact`, `/privacidad` ↔ `/en/privacy`, `/blog` ↔ `/en/blog`, `/blog/<slug>` ↔ `/en/blog/<slug_en>`, `/ingresar` ↔ `/en/sign-in`, `/referidos` ↔ `/en/referrals`, `/servicios` ↔ `/en/services`, `/recetas` ↔ `/en/recipes` (`/en/tastes` and `/en/gustos` go to `/en/about`). **The URL sets the language**, for the content and the metadata: `src/proxy.ts` sets the `x-lulox-locale` header from the path (overwriting any client value) and rewrites `/en/...` to the Spanish page that renders it. The `lulox-locale` cookie only remembers the last choice in the language switch; it is never used to redirect or pick a language (neither is `Accept-Language`). The switch opens the same page in the other language (on an article, its other slug, read from the page's `hreflang`). The map lives in `src/lib/routes.ts` (`SEGMENTS_ES_TO_EN`); internal links are written in Spanish and go through `href()` from `useLocale()`. Old English paths at the root (`/about`, `/projects`, `/contact`, `/privacy`, `/login`) keep redirecting to the Spanish ones as before.
- **Share cards (SEO):** every URL has its own `og:title`, `og:description`, `twitter:*`, `og:url` and `canonical`, in the URL's language: `og:locale` `es_AR` at the root and `en_US` under `/en` (no cookies, no `Accept-Language`). Every page has `hreflang` `es-AR`, `en-US` and `x-default` (= Spanish), and `sitemap.xml` lists both versions of each page with their alternates. Format is "Page | {name}"; the home has a fixed pitch title, description and keywords in `src/content/home-copy.ts` (`meta`, ES and EN), not the D1 description. Articles use their title and `summary` in that language (if the summary is missing, the start of the article); other pages have their own short description in each language. The helper is `src/lib/page-metadata.ts` (`pageMetadata("/spanish-path", { es, en })`); each route's copy lives in its `layout.tsx` (or `privacidad/page.tsx`). When you add a route, add it to `SEGMENTS_ES_TO_EN` and give it a `pageMetadata(...)` call.
- `wrangler.jsonc` and the footer link in `src/components/views/home-view.tsx`.

### McpRpc

`lulox-mcp` talks to this Worker only through a service binding to the `McpRpc` entrypoint (`export class McpRpc extends WorkerEntrypoint` in `worker.ts`). It is not mounted on the default `fetch`: the `www` redirect, the scanner 404 and the rate limit do not run on that call. Each method builds an internal `Request` to `https://lulox.com.ar/api/mcp/*` with `Authorization: Bearer <MCP_SERVICE_TOKEN>` and passes it to the OpenNext handler (`handler.fetch`). The `RpcResult` mapping (`{ok:true, data}` or `{ok:false, error:{code, message}}`) lives in `src/lib/mcp-rpc.ts`, which does not import `cloudflare:workers`.

| Method | Internal request | On success |
|---|---|---|
| `uploadImage({filename?, contentBase64})` | `POST /api/mcp/media` as JSON (`contentBase64` on the body that route already accepts) | `{url, key}` |
| `createDraft({title, summary, body, slug?, tags?, topics?, coverImage?, images?, slides?})` | `POST /api/mcp/posts` | `{slug, slugEn, published: false, needsTranslation, previewUrl}` |
| `publishPost({slug, confirm})` | `POST /api/mcp/posts/<slug>/publish` with `{confirm: true}` | `{slug, slugEn, published: true, alreadyPublished}` |
| `listPosts({drafts?})` | `GET /api/mcp/posts`, or `?drafts=1` when `drafts` is the boolean `true` | `{items}` |
| `getPost({slug})` | `GET /api/mcp/posts/<slug>` | the post, or `not_found` when it is missing |

`confirm` must be the boolean `true`. Missing, `false`, or the string `"true"` is `invalid` with message `confirm_required`, and the route is not called. With `MCP_SERVICE_TOKEN` unset (or only whitespace) the result is `not_enabled` with message `blog MCP not configured`, also without calling. HTTP mapping: 2xx returns the JSON without the `ok` field; 400 and 409 are `invalid` (the message is the code, for example `slug_taken`); 404 is `not_found`; 401 and 503 are `not_enabled` (`blog MCP not configured`); anything else is `internal` with a generic message. That message has no stack, no SQL and no secret.

### 🖱️ Cursor convention

Everything clickable shows `cursor: pointer` and anything disabled shows `cursor: not-allowed`. A global rule at the end of `src/app/globals.css` handles it (links, buttons, clickable ARIA roles, `label[for]`, `select`, `summary`, range/checkbox/radio/submit/file/color inputs and their thumbs), so new components need nothing extra. Intentional exceptions: `.sec-reorder-handle` (`grab`) and `.md-acc-btn-edit` (editable container). To check it: with `pnpm dev` running, `pnpm audit:cursor` walks every route in Spanish and under `/en` (home, blog and articles, hire, about, projects, contact, tastes, rothko, privacy, sign-in, 404) in light/dark with headless Chrome and fails if anything clickable has the wrong cursor (`AUDIT_URL`, `AUDIT_ROUTES`, `AUDIT_WAIT=load` to target another site). To walk it as admin, pass a local session with `AUDIT_COOKIE="better-auth.session_token=..."` (only against your local preview). Typing fields (text, number, search, date) keep the text cursor.

## 🦝 Site identity

The name, description, socials, booking link, avatar and palette are not in the repo. They live in D1 (`site_settings`) and are edited in admin mode. A fresh clone starts from neutral defaults (name "Portfolio", blue accent). The about story and the blog bio have generic text in `src/i18n/messages.ts`; if D1 already has `site_copy` for those keys, the database wins.

### 💼 Hire

`/contratar` has a simple form (name, email and a message of up to 1000 characters). There is no public price list: the cost is estimated on a call. The booking button comes from `site_settings` (`call_booking_url`); if it is empty, it is not shown.

### 📊 Visits

`/admin/visitas` (only `lucianoolivabianco@gmail.com`, like the rest of the admin) shows visits per day and per source, plus a cut of `/contratar` and `/en/hire`. The Worker stores in D1 (migration `0016_page_visits.sql`) the day (Argentina time), the path, `utm_*`, the referrer host and the country (`CF-IPCountry`). It does not store IP addresses, cookies or user agents. The Cloudflare dashboard is at [Analytics & logs → Web Analytics](https://dash.cloudflare.com/124b4210ff80c15610ed109083a5cf95/web-analytics).
